An action item from a meeting needs three things to count as real: a specific task, one named owner, and a due date. "We should look into the vendor pricing" is a discussion point. "Raj checks vendor pricing by Friday" is an action item. The difference matters because only the second one has anyone accountable for it happening.

## What Makes Something an Action Item

Not everything said in a meeting is an action item, and treating every comment like one buries the ones that matter. A real action item is a task someone can start without asking a follow-up question — it names what needs to happen, who's doing it, and by when. If any of those three pieces is missing, it's not ready to leave the meeting yet; someone needs to nail it down before the call ends.

## The Owner and Deadline Rule

Every action item gets exactly one owner, even for work that involves several people. "The team will update the doc" is not assignable — nobody checks whether "the team" did it. "Priya updates the doc by Wednesday" is. If a task genuinely needs two people, pick one as the owner responsible for making sure it happens and let them pull in the second person.

The deadline doesn't need to be precise to the day for everything, but it needs to exist. "Soon" is not a deadline anyone can be held to.

## Extracting Action Items: During vs After the Meeting

**During the meeting:** the moment someone says something that sounds like a commitment, say it back as an action item out loud — "so that's you, by Friday?" It takes five seconds and catches ambiguity (wrong owner, no real deadline) while the person who made the commitment is still in the room to correct it.

**After the meeting:** if you're working from a transcript or an [AI meeting notes](/blog/ai-meeting-notes) summary, scan specifically for commitment language — "I'll," "we'll," "by [date]" — and check each one has a clear owner before it goes into the final notes. This is also where it's easy to over-collect: not every "I'll think about it" is an action item worth tracking.

## Where Action Items Should Go

| Destination | Good for | Tradeoff |
|---|---|---|
| Task tracker (Linear, Asana, Jira) | Work that needs status tracking over days or weeks | Someone has to actually open it to see it — invisible if the team doesn't check the tracker |
| Team chat (Slack) | Fast visibility, quick follow-up | Scrolls out of view fast; bad for anything that needs tracking past a day or two |
| Meeting notes doc / email recap | Record-keeping, who-said-what-when | Not a task system — nobody "closes" an action item in a doc |

The real-world answer is usually two of these at once: the task tracker holds the work, and a chat message or notes doc gives it visibility the moment it's created. Picking only the doc is the most common failure mode — the action item is recorded correctly and still never gets done, because recording isn't the same as tracking.

This is also why [a consistent meeting minutes template](/blog/meeting-minutes-template) matters: if action items always live in the same section with the same three fields (task, owner, due date), copying them into a tracker takes seconds instead of requiring someone to reconstruct what was actually meant.

## Common Mistakes

1. **No single owner.** Shared ownership is the single most common reason an action item quietly dies.
2. **Buried in a long notes doc.** If finding an action item requires scrolling through a full meeting summary, it won't get checked regularly.
3. **No follow-up mechanism.** Writing the action item down is step one. Reviewing open ones at the start of the next related meeting is what actually closes the loop.
4. **Over-collecting.** Turning every stray comment into a tracked task creates a backlog nobody trusts, which makes people stop checking it.

## FAQs

### What's the difference between an action item and a discussion point?
An action item has a specific task, a named owner, and a deadline. If any of those three is missing, it's still a discussion point, not an action item yet.

### Should action items go in the meeting notes or a separate task tracker?
Both, ideally. The meeting notes are the record of what was decided; the task tracker is where the work actually gets managed. Copying action items into a tracker right after the meeting is what keeps them from getting lost.

### Who should own an action item if the group decided on something together?
One person, always — even if the task affects multiple people. Shared ownership with no single name attached is the most common reason action items don't get done.

### How do you follow up on action items without micromanaging?
Review open action items at the start of the next related meeting, not in a separate check-in. It takes two minutes and makes follow-up part of the normal rhythm instead of a special event.
