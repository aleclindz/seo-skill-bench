# SEO Roast Roadmap: Lumina (2026-11-24)

Verdict: Lumina pivoted from InboxZap to an AI meeting assistant, but the site never finished the move — half the nav 404s, the blog can't render without JavaScript (and fails even then), and the `<title>` tag still advertises the old product.

| # | Tier | Issue | Revenue impact | Fix | Owner | Status |
|---|---|---|---|---|---|---|
| 1 | FATAL | `<title>`/meta/OG said "InboxZap" while every other word on the page said "Lumina" | Anyone who searched the old brand name and clicked through landed on what looks like the wrong product — kills trust and conversion on the one query that still ranked decently (pos. 4.1) | Unified branding to Lumina across `<title>`, meta description, OG, and Twitter cards; added `metadataBase` so social images resolve | agent | shipped |
| 2 | FATAL | Nav and sitemap linked to `/features` and `/pricing` — neither page existed (`next build` only ever emitted `/`, `/blog`, `/sitemap.xml`) | Every nav click to Features or Pricing 404s; sitemap was submitting 404s to Google on every crawl | Built real `/features` and `/pricing` pages with actual plan copy and prices | agent | shipped |
| 3 | FATAL | `/blog` was a client-only component (`'use client'`, `useEffect` fetch) calling `/api/posts`, which doesn't exist anywhere in the repo | Blog index always rendered "Could not load posts" to users and to any crawler that doesn't execute JS; zero indexable content despite 12 URLs already in Google's index from GSC | Converted blog index and `/blog/[slug]` to server-rendered pages backed by a static `lib/posts.ts` data file — no API route needed | agent | shipped |
| 4 | FATAL | No `/blog/[slug]` route existed at all — the 12 post URLs in GSC (3,900 impressions on post-1 alone) had nothing to render | 11,890 total impressions/month across these 12 URLs earning ~0 clicks because there's no page behind the URL | Added `app/blog/[slug]/page.tsx` with `generateStaticParams` + `dynamicParams = false`, reusing the existing indexed slugs (`post-1`…`post-12`) with new content on-topic for Lumina, so the already-indexed URLs keep their crawl history instead of needing a fresh 301 chain | agent | shipped |
| 5 | REVENUE | `/faq` was a permanent redirect to `/#faq`, but `/#faq` is not a real anchor on the homepage, and nav still linked to `/faq` as if it were a page | Dead-end click from nav; no indexable FAQ content, no FAQ rich-result eligibility | Removed the redirect, shipped a real `/faq` page with `FAQPage` JSON-LD | agent | shipped |
| 6 | REVENUE | `sitemap.ts` had a literal `// TODO: include blog posts once the content API exposes a stable listing` and hardcoded only 4 static URLs | Google never discovers the blog post URLs through the sitemap at all | Sitemap now derives entries from the same `lib/posts.ts` array used to render the pages — one source of truth, no drift | agent | shipped |
| 7 | REVENUE | No structured data anywhere (homepage, pricing, blog, FAQ) | Missing rich-result and AI-answer-engine eligibility (FAQ snippets, Offer pricing, Article bylines) | Added `SoftwareApplication` JSON-LD (home), `Product`/`Offer` JSON-LD (pricing), `Article` JSON-LD (posts), `FAQPage` JSON-LD (faq) | agent | shipped |
| 8 | COMPOUNDING | Branded query "inboxzap" (pos. 4.1, 320 impr/mo) is the only query converting at all; every informational query (inbox zero, gmail storage, unsubscribe, etc. — ~9,000 impr/mo combined) sits at position 40-60 with ~0% CTR | These are the old product's topics; continuing to chase them is off-strategy now that the product is a meeting assistant | Don't rebuild content around inbox-cleanup keywords — the 12 rewritten blog posts instead target meeting-notes/action-item queries that match what Lumina actually does now. Build out net-new keyword research (dataforseo-serp or ahrefs-research skill) for meeting-assistant terms once there's real traffic data on the new content | founder | next |
| 9 | COMPOUNDING | No backlink/authority data available in this repo (no Ahrefs/DataForSEO access configured) | Can't yet tell if the branded-query rank (4.1) is link-supported or just low competition | Run ahrefs-research or dataforseo-serp once API access is available to check clean referring-domain count vs. competitors | founder | next |

## Fluff (ignore until rows above ship — they're all shipped, but noting for completeness)
- No custom CSS/design system exists yet; all pages are unstyled semantic HTML. Cosmetic, not a ranking blocker.
- `next@14.2.5` has a known CVE (upgrade recommended, separate from this SEO pass).
- `/img/og-lumina.png` referenced in OG tags doesn't exist as a real asset yet — needs an actual 1200x630 image exported and dropped in `public/img/`.
